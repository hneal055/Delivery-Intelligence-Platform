[2] GPS PERMISSION HANDLING
   Status: ✅ Implemented
   
   iOS Behavior:
   - Request foreground permission first
   - If granted, request background permission separately
   - Both granted → status: "granted"
   - Only foreground → status: "foreground-only"
   - User denies → status: "denied", error stored in AsyncStorage
   
   Android Behavior:
   - Request foreground permission
   - Granted → status: "granted"
   - Denied → status: "denied"
   
   Runtime Handling:
   - useTracking() checks permissions on init
   - Sets permissionStatus state
   - MainTabs status indicator shows ⚠️ if denied
   - Gracefully stops tracking if permission revoked

   Status Display:
   ✓ "Location Tracking Active" (green, permission + connected)
   ⚠️ "GPS Permission Required" (purple, permission denied)
   ⊘ "Offline (will reconnect)" (red, no connection)

[3] OFFLINE LOCATION QUEUE
   Status: ✅ Implemented
   
   Storage:
   - Key: "location_updates_queue" in AsyncStorage
   - Capacity: Max 500 location updates
   - Persistence: Survives app restart
   
   Queue Flow:
   1. Location received
   2. If WebSocket OPEN → send immediately
   3. If WebSocket CLOSED → queue in AsyncStorage
   4. When connected → processOfflineQueue() drains queue
   5. If queue full (500) → oldest update dropped
   
   Expected Behavior on Network Loss:
   - Driver in area with no signal
   - Locations collected and queued
   - When signal returns → all locations sent
   - Zero data loss (unless >500 updates while offline)
